# Version 0.4.0 <span class="timestamp-wrapper"><span class="timestamp">[2026-10-26 Mon]</span></span>

-   Added `rake docs:doctor` to suggest documentation improvements, identifying the relevant file without changing files or running examples.
-   README generation now displays the consuming gem's version and refreshes it when the gemspec version changes, preserving the rest of the README.
-   Protect handwritten Markdown: generated `README.md` files now begin with `<!-- Generated by gem_docs -->`. Existing files without that exact first line will not be overwritten. To continue generating an older README, review and back it up, then add the marker as its first line.
-   New README skeletons include the configured code-block headers. Default Ruby headers now use `:eval never-export`, so `docs:all` executes examples once and exports their saved results. Existing headers are preserved; replace `:eval yes` to adopt this behavior. After editing examples, run `docs:tangle` before exporting, or use `docs:all`, to refresh results.
-   Improved execution and export reliability: skip disabled examples, preserve inherited and per-block settings, and report Emacs failures, confirmation prompts, and timeouts instead of silently succeeding or waiting indefinitely. Failed README exports preserve the previous Markdown output.
-   Fixed repeated and empty overview comments, including when the README lacks the configured introduction section. Overview extraction also handles a section at the start of the README and gems defined with a class.
-   Preserve existing `.yardopts` settings and require YARD 0.9.28 or newer for compatibility with supported Ruby versions.
-   Fixed explicitly configured workflow badge URLs. `docs:headers` is now the canonical task name; `docs:header` remains an alias.
