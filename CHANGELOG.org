* COMMENT CHANGELOG tips:
1. Don't dump your git change logs into this file, write them yourself.
2. Keep entries short and user-focused,
3. Use non-technical language, but do speak in the vocabulary of your gem.
4. Don't document changes only of interest to the programmers, just those the
   user would find useful.
5. Give each heading an inactove date (C-c ! is useful here) and a version
   number.

* Version 0.4.0 [2026-10-26 Mon]
- Added ~rake docs:doctor~ to suggest documentation improvements, identifying
  the relevant file without changing files or running examples.
- README generation now displays the consuming gem's version and refreshes it
  when the gemspec version changes, preserving the rest of the README.
- Protect handwritten Markdown: generated ~README.md~ files now begin with
  ~<!-- Generated by gem_docs -->~. Existing files without that exact first
  line will not be overwritten. To continue generating an older README,
  review and back it up, then add the marker as its first line.
- New README skeletons include the configured code-block
  headers. Default Ruby headers now use ~:eval never-export~, so
  ~docs:all~ executes examples once and does not re-evaluate them on
  export to README.md. Existing headers are preserved; replace ~:eval
  yes~ to adopt this behavior. After editing examples, run ~docs:tangle~
  before exporting, or use ~docs:all~, to refresh results.
- Improved execution and export reliability: skip disabled examples, preserve
  inherited and per-block settings, and report Emacs failures, confirmation
  prompts, and timeouts instead of silently succeeding or waiting indefinitely.
  Failed README exports preserve the previous Markdown output.
- Fixed repeated and empty overview comments, including when the README
  lacks the configured introduction section. Overview extraction also
  handles a section at the start of the README and gems defined with a
  class in addition to module as previously.
- Preserve existing ~.yardopts~ settings and require YARD 0.9.28 or newer for
  compatibility with supported Ruby versions.
- Fixed explicitly configured workflow badge URLs. ~docs:headers~ is now the
  canonical task name; ~docs:header~ remains an alias.

* Version 0.3.1 [2025-12-27 Sat]

- Added export of CHANGELOG.org to CHANGELOG.md;
- Added CHANGELOG skeleton along with README; tasks are now
  `rake docs:skeleton:readme` and `rake docs:skeleton:changelog`.
- Added this CHANGELOG so I have an example to use in my specs.  Oh, and for
  users also.
* Version 0.2.0 [2025-12-23 Tue]
- Make tangle of README.org unconditional, even is it is not newer than
  README.md.  The code examples depend on more than just the text of
  README.org, they especially depend on changes to the gem's lib code, so
  running unconditionally is usually what is wanted.
- Before docs:tangle, kill the session buffer for ruby code blocks so each run
  is independent of prior runs and the current version of the gem lib gets
  loaded.
